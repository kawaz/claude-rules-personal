新しい知見は、その時に着手中のプロジェクトが最先端になりがちで、reference や他のプロジェクトには多少遅れて反映されていく。あるプロジェクトがいつまでも最新の基準であるわけではない (kawaz 2026-11-15)。

**Why**: 古い実装のプロジェクトを「利用者の実態」として設計の根拠にしかけた。逆に、ある時点で最新だったプロジェクトを、後になっても基準として引き続けるのも同じ誤り。

**How to apply**: 別のプロジェクトの実装や reference を手本・根拠にする前に、それが今も最新の考え方を映しているかを確かめる (最近の着手状況、作り直しの予定、同じ領域でもっと新しく着手したプロジェクトの有無。分からなければ kawaz に聞く)。「X が最新の基準」と記録する時は時点 (YYYY-MM-DD 時点) を必ず添え、後で読む時は時点が古ければ確かめ直す。着手中のプロジェクトで得た知見は、reference への反映が遅れていることを前提に、気づいた時に reference へ戻す。
