## フェーズ B: `--json` の実装

**B-1. グローバルフラグ `--json` の定義**
CLI フレームワークのグローバルオプションとして追加し、`--help` に表示されること、全サブコマンドで受理されることを確認する。この時点では挙動を変えなくてよい。

**B-2. サブコマンドごとの出力スキーマ定義**
各サブコマンドの結果データ構造にシリアライズ定義（フィールド名は snake_case か camelCase かを 1 つに統一）を付ける。サブコマンド数だけ分割可能なので、コマンドが多ければ 1 コマンド 1 TODO に割ってよい。

**B-3. トップレベル構造の決定と実装**
全コマンド共通のエンベロープを決めて実装する。最低限 `schema_version` を含めること（後方互換の判断材料になる）。完了条件: 全サブコマンドの `--json` 出力が同じ外枠を持つこと。

**B-4. エラー時の JSON 出力**
異常終了時も `--json` 指定なら JSON でエラーを返す（例: `{"error": {"code": ..., "message": ...}}`）。**exit code は従来と変えない**こと。完了条件: 主要なエラー系統ごとに JSON が返り、exit code が非 JSON 時と一致すること。

**B-5. 他フラグとの相互作用の決定**
`--quiet` / `--verbose` / `--color` / 対話的プロンプトと `--json` の組み合わせ挙動を決めて実装する（推奨: `--json` はプロンプトを禁止し、TTY 判定による色付けを無効化）。完了条件: 組み合わせ表がドキュメント化され、その通りに動くこと。

**B-6. JSON 出力のテスト**
各サブコマンドについて (a) 出力が JSON としてパース可能、(b) スキーマのスナップショット一致、(c) exit code の一致、を検証するテストを追加。完了条件: CI で回ること。
