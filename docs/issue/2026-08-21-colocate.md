# colocate 新構成への移行台帳 (bare+jj 方式 56 リポの進捗管理)

## 概要

bare git + jj workspace 方式 (旧) の全リポを colocate + 親ガード方式 (新標準、正本は
`jj-colocate-workflow` skill) へ入れ替える。進め方の裁定:

1. 低リスクリポ (workspace が main のみ & 未 push なし & clean) は一括移行を先行
2. 主要リポは本台帳でステータス管理 (未着手 / 移行済み / 要判断)
3. kawaz/* 以外 (kawaz123 / zunsystem) は認証境界が異なるため、実施は各面のセッションに振る

## 背景

kawaz 裁定 (2026-08-21) により、移行プロジェクトの管理をルールリポの issue へ引き継いだ。

### 移行手順

`jj-colocate-workflow` skill の §移行が正本。旧構成は削除せず `<repo>.old-bare-<date>` に
mv 退避し、kawaz の削除判断を待つ。実体パスが `{repo}/main` で不変のため、作業中セッションの
開き直しは不要 (第 1 号で実証)。

## 受け入れ条件

- [x] 低リスク 12 リポの一括移行が完了し、各リポで検証 (ガード実効 / main 一致) が通る
- [ ] 要判断リポの扱いが個別に決まり、台帳が全行チェック済みになる
