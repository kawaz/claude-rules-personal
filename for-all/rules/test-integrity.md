# 既存のテストを自分の都合で書き換えない

テストが fail したとき、**入力の書き換え・assert の緩和・timeout 延長・暗黙 skip・削除で green に戻すのは禁則**。テストは仕様の境界を固定した線で、実装の都合で動かしてよいものではない。直すのは真因。即直せないなら `#[ignore = "<理由 + 追跡 ref>"]` で意図を保ったまま明示 skip して issue を起票する (green は「直った証拠」、ignore は「直していないことの可視化」)。「flaky」「環境依存」と書きたくなった瞬間が手抜きシグナル。

テストコードを書く・直す・落ちたテストに手を入れるなら、先に reference の `testing/_index.md` ([[knowledge-guide]] のパス) を読む (何のために書くか、網羅観点、コメント様式、flaky の説明責任)。
