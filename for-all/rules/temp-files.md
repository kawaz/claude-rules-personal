# 一時ファイル・ディレクトリの置き場

作業で作る一時的なファイル・ディレクトリは**すべて**、Claude Code の scratchpad ディレクトリか `mktemp -d` で作ったディレクトリ (以下ベース) の中に置く。`/tmp/foo` のような固定名で直接作らない (名前が衝突し、どの作業の残骸か分からなくなる)。

対象はツールの実行に限らない: テストコードが作るファイル、実験の環境 (config home・state dir・socket・ログ)、worker / サブエージェントの作業場所、起動したプロセスが副作用で作るディレクトリも含む。

- **worker を使う時**: 親が `mktemp -d` でベースを 1 つ作り、その**実パス**を子へのプロンプトに書く (Bash の変数は呼び出しをまたいで残らない)。子はその中に `mktemp -d -p <ベース>` で自分用のディレクトリを作って作業し、ベースの外に作らない。後始末は親がベースごと行う
- **テストコード**: `mkdtemp` 等のランダム名の一時ディレクトリを使い、終わったら片付ける (固定パスに書かない)
- **Unix socket**: パス長の制限 (sun_path) は bind / connect に渡すパス文字列の長さの制限で、置き場の制限ではない。パスが長くなる時は、そのディレクトリに cd してから相対パスで bind / connect する。置き場をベースの外や別の短いパスに分けない
- **起動したプロセスの置き場**: state / config / runtime dir は環境変数 (`XDG_*_HOME`、`TMPDIR`、アプリ固有の変数) でベースの中に向け、副作用がベースの外に出ないようにする。終了後にベースの外へ何か作られていないか確認し、出ていたら片付ける
- **後始末の `rm`**: ベースの中でも auto mode の classifier に止められることがある。止められたら [[classifier-notes]] に従う

Why: 置き場が作業ごとに 1 か所に閉じていれば、衝突せず、後始末がベースの削除 1 回で済み、残骸が出ない。
