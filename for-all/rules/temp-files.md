# 一時ファイル・ディレクトリの置き場

作業で作る一時的なファイル・ディレクトリは**すべて** `$TMPDIR` の中に置く。セッションの `TMPDIR` は起動時に `<プロジェクト>/tmp.local/<セッション id>/` に向いていて、その中は自由に使ってよい (`tmp.local/` は VCS の ignore 対象で、コミットに混ざらない)。`/tmp/foo` のように `$TMPDIR` の外へ直接作らない。

- **作り方は自由**: 固定名でも `mktemp` / `mktemp -d` でもよい (`mktemp` も `$TMPDIR` の中に作る)
- **後始末は要らない**: セッションが動いている間は消えず、終了後も 10 日は残り、その後自動で消える。自分で消してもよい。それより長く残したいものは一時置き場に置かない
- **`TMPDIR` が `tmp.local/` の下を向いていない時**: `tmp.local/<セッション id>/` を自分で作って使う (既にあればそのまま使う)
- **worker を使う時**: worker も同じ `$TMPDIR` を使う。並行する worker どうしで固定名がぶつからないよう、worker ごとにディレクトリを分ける (worker が `mktemp -d` するか、親が実パスをプロンプトに書く)
- **テストコード**: `mkdtemp` 等のランダム名の一時ディレクトリを使い、終わったら片付ける (他の環境でも走るので期限を当てにしない)
- **Unix socket**: パス長の制限 (sun_path) は bind / connect に渡すパス文字列の長さの制限で、置き場の制限ではない。長くなる時は、そのディレクトリに cd してから相対パスで bind / connect する。置き場を `$TMPDIR` の外に分けない
- **試しに起動するプロセス**: そのプロセスが設定・状態・socket・ログを書く先を、環境変数 (`XDG_*_HOME`、アプリ固有の変数) で `$TMPDIR` の中に向ける (実運用の置き場に書かせない)。終了後に外へ何か作られていないか確認し、出ていたら片付ける
- **`rm` が止められた時**: [[classifier-notes]] に従う

Why: 置き場がセッションごとに 1 か所に閉じていれば、衝突せず、期限で消えるので残骸が出ない。
