# TypeScript の型の付け方の水準

TypeScript を書く時は、型の付いていない値が境界より内側に流れ込む経路をゼロにする。型は主張でなくスキーマから得る。

## 水準

- **データの形はまずスキーマで定義し、型はそこから導く**。型とスキーマを別々に書かない。スキーマのライブラリはプロジェクトで 1 つに決める (スキーマから型を導け、失敗を値で返せるモダンなもの。例: valibot / zod)
- **外から来るデータは受け取った境界でスキーマに通す** (JSON、外部コマンドの出力、ファイル、HTTP / WebSocket、ストレージ、stdin)。結果は型付きの値か型付きの失敗にする。「validate して使う」ではなく「parse して型を付ける」(`JSON.parse` は文字列を値にするだけで parse ではない)
- **関数の引数と戻り値はすべて具体的な型で書く**。`unknown` を受けて中で調べる関数を作らない。`unknown` が出てよいのは `catch` の束縛と、スキーマに通す直前の境界の 1 か所だけ
- **`as` による型の主張 (`as const` を除く)、`any`、非 null の主張 `!` は使わない**。型が合わない時は主張で黙らせず、スキーマに通すか型の設計を直す (値が無い場合は型で表して分岐で扱う)
- **lint で機械的に検査する**。typescript-eslint / oxlint の該当規則を有効にする

## 自警 (書きたくなった瞬間が境界でスキーマに通していないサイン)

- `as Foo` / `<Foo>x` / `x!`
- `(x: unknown)` / `Record<string, unknown>` の引数
- `?? String(x)` のような型の穴を埋めるフォールバック、throw を包む try/catch の継ぎ足し
- `isRecord` / `typeof x === "object"` を重ねる手書きの型ガード関数

スキーマ定義・境界の書き方の具体例と lint の設定は reference の `typescript/schema-first-typing` を読む。

Why: 型の付いていない値が内側へ流れると使う場所ごとに検査が継ぎ足され、検査の漏れが実害になる。主張された型は嘘をつける。
