# 裁定・確認待ちは docs/QUESTIONS.md に常時集約

## AskUserQuestion 使用禁止

**Why**: タイムアウト無しで無限待ち、リモート応答不可、ユーザ入力中の割り込み不快、総じてUX悪い

## docs/QUESTIONS.md

ユーザ裁定が必要な事項 (設計分岐・命名・不可逆操作の可否など) と、実装完了後に
依頼する**実機確認**を、チャット提示と**同一ターン**でプロジェクトの
`docs/QUESTIONS.md` に記録する。チャットは「👺TNG-Q1 の裁定お願いします」の
**👺 + ラベル ID** 参照だけにし、正本はファイルが持つ。回答は「SEC-Q6=a」の
ようにラベル + 選択肢記号で通じる形。

**確認待ちを載せる理由**: 「実機確認お願いします」の直後にユーザが次の要望を
投げると確認依頼が TL に流れ、何が未確認か分からなくなる (kawaz 2026-07-26)。

## テンプレート (ファイルが空ならこれをコピーして書き始める)

規約の正本は本 rule (冒頭の引用ブロックはゼロコンテキスト読者向け要約)。

```markdown
# 裁定・確認待ち一覧 (ユーザ用)

> 運用規約 (ゼロコンテキスト読者向け、正本は claude-rules-personal の
> `questions-md-registry` rule):
> - 裁定待ち = ユーザの判断が要る項目。確認待ち = 実装済みで実機確認を待つ項目
> - ラベルはバッチ / セッション毎に一意な短プレフィクス (XX-Q1 / XX-C1 形式、
>   Qn 単独の使い回し禁止、長期一意性は不要)
> - 👺 は「いま待っている項目」とチャットの依頼文にだけ付ける
>   (裁定済み・過去参照に付けない。ユーザは正規表現でハイライト/アラームしており
>   誤陽性が有害)
> - チャット提示と同一ターンで本ファイルに記録 + path 指定 commit
> - 裁定が下りたら該当セクションを即削除し、内容は正規の記録先 (DR / issue /
>   journal) へ反映。本ファイルは常に「現在待ち」だけを持つ
> - 確認待ちの削除条件: ユーザが確認 OK を返した / 後続リリースで当該実装が
>   上書きされ確認対象でなくなった
> - 参照パスはリポ内相対 (リポ外はフルパス)

## 裁定待ち

### 👺XX-Q1: <質問要旨>
- a (推奨): …
- b: …

#### 背景説明 (初回は省略、詳細を求められたら補充)

## 確認待ち

### 👺XX-C1: <確認要旨> (vX.Y.Z)
確認してほしい内容を簡潔に。実装したバージョンを添える。

#### 確認手順 (基本省略、複雑な場合のみ)
- 箇条書きで簡潔かつ具体的に
```

## ファイル規約

- 場所: リポ管理プロジェクトの `docs/QUESTIONS.md` (commit する)。リポの無い作業では適用外
- 粒度は**索引**: ラベル + 要旨 1〜2 行 + 選択肢と AI の推し (根拠 1 文) + 参照 (リポ相対パス)。詳細の正本は findings / issue / DR 側に置き複製しない
- **1 項目 = 1 セクション、選択肢は箇条書き**。複数 Q の 1 セクション列挙や選択肢の 1 行詰め込みをしない (kawaz 2026-07-23)
- 絵文字 👺 は固定。ユーザは `👺\s*[A-Za-z0-9α-ωΑ-Ω\-]{2,}` でハイライト / アラームしている

## 更新規律

- 提示と同一ターンでファイル更新 + path 指定 commit (push はリリース窓に同乗)
- 裁定が下りたら該当セクションを**削除**し、内容は正規の記録先 (DR / issue / journal / close_reason) へ反映。ファイルは常に「現在待ち」だけを持つ (経緯は git log と各記録先が担う)
- 回答が新しい Q を生んだ場合 (前提棄却・逆質問)、旧 Q の削除と新 Q の追記を同時に行う
- 調査中で提示に至らないものは載せない (ユーザが今答えられる / 今確認できる形になったものだけ)

## 説明要求への応答はファイル内セクション補充で

「説明して」「詳しく」「それ何?」と返されたら、**チャットで長々説明しない**
(TL に流れて参照コストが高い)。当該 Q を QUESTIONS.md 内で「#### 背景説明」等の
サブセクション付きで**書き直して再提示** (背景・機構・具体例を self-contained
に) し、チャットは「👺HO-Q5 を説明付きで再提示しました」の参照だけ返す。前提
知識が要る Q は初回から説明セクションを添えるのが望ましい (kawaz 確認「説明が
TL に流れず良い感じ」)。

## Why

- ユーザが「何待ちか」をチャット履歴から掘り返す手間削減
- AI にリストと説明を再生成させるコストの削減 (今何待ち? を撲滅)
- セッション境界・並行セッションを越えて裁定・確認キューが共有される
