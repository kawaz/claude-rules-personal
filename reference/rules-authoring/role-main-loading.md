# ロードリストの規律 (role-main)

統括メインがセッション開始時に読むものは、3 段のロードリストで決まる。各段の索引がそのまま「何を読むか」の正本になる。

| 段 | 場所 | 内容 |
|---|---|---|
| 段 1 | claude-rules-personal の `reference/role-main/_index.md` | 面によらず共通 |
| 段 2 | 現在の面の overlay ルールリポの `reference/role-main/_index.md` | その面の業務知識 |
| 段 3 | cwd のプロジェクトの `CLAUDE.md` | そのプロジェクトの起動時手順 |

段 1 → 段 2 → 段 3 の順に辿る。段 2 の overlay のパスは、その面の rule が案内する (面の判別と越境は `claude-config-dir-isolation` rule)。

worker / reviewer role はこのリストを読まない (必要なものを agent 定義の frontmatter で明示指定する)。

## 必読 / 必要時の 2 節構成

**全段の index を同じ 2 節構成で書く**:

- **必読** — 載っていないと事故るもの。セッション開始時に順に Read する
- **必要時に読む** — その作業に入ってから読めば足りるもの。エントリには参照知識と同じ発火語を付ける (index-conventions)

索引 2 本 (`reference/_index.md` と `memory/_index.md`) は必読に置く。本文は必要時にその 1 ファイルだけ Read する。

## 必要時 → 必読への昇格

必要時側に置いたドキュメントについて、kawaz から「ちゃんと読まずに作業してる?」「それってやり方違わない?」「どっかにあったよね?」「決めた気がする」のようなシグナルが出たら、その対象が必要時リストにあるかを確認する。あれば **kawaz に確認したうえで必読へ移す** (「必要時に置いていたが読まずに事故ったので必読へ上げてよいか」と聞く)。kawaz が「まだ様子見」と言えば移さない。

昇格は必読側を太らせるので、上げたものが本当に毎セッション効くかを確認する。特定の作業でしか効かないものは、必要時に残したまま発火語を足す方が効く (読まれなかった原因が「リストに無い」ではなく「引けない」ことが多い)。
