# rule / skill / 参照知識の分類

書く前に「常時ロード rule」「skill」「参照知識」のどれかを判定する。判定は 2 段階。

## 段 1: 常時ロードか、それ以外か

「この内容が context に無いターンで事故が起きるか?」

- 起きる → **常時ロード rule** (`for-*/rules/`)。毎ターンの判断に効く**行動制約 (constitution)** = 禁則・自警・評価軸だけを置く
- 特定の作業に入ってから読めば足りる → それ以外。**手順・表・テンプレ・コマンド列は常時ロードに置かない**

1 ファイルに両方が同居しそうになったら分割する (= 禁則だけ rule に残し、手順は参照知識へ降ろして rule から名前で指す。手順は migration)。

## 段 2: skill か、参照知識か

**ユーザがスラッシュコマンド (`/名前`) で起動するものか**、の一点で決める。

- ユーザが起動する → **skill** (`skills/<slug>/SKILL.md`)。本文がそのまま投入プロンプトとして働くもの (`$ARGUMENTS` を受ける)、または frontmatter が harness 機能 (`context: fork` / `agent:` 等) を使うもの
- AI が必要になった時に読むだけ → **参照知識**

知識・runbook 系は skill にしない。**スクリプトやテンプレを持っていることは skill の理由にならない** (参照知識のトピックディレクトリにリソースとして同梱できる。reference-layout)。

skill は plugin として配られるので、編集しても `plugin-release` を通すまでどこにも効かない。参照知識は実体を直接 Read するので配布が要らない。この差も「読むだけのものを skill にしない」理由になる。

## 参照知識の書き先 (3 層 + auto-memory)

層のパスは `knowledge-guide` rule の表が正本。書き先は次で決める:

- そのプロジェクトでしか意味を持たない → そのプロジェクトの auto-memory
- 別プロジェクトでも効くが一般化前 → `memory/`
- 個人情報系 → privacy リポ
- 公開してよい体系知識 → `reference/`
- 全セッションで毎ターン効く行動制約 → rule
- 業務面 (取引先・業務システム等の固有名詞を含む) → その面の overlay リポの同じ 3 層 (`sanitize-work-identifiers` rule)

昇格させたら下層の元エントリは消す (正本の二重化を避ける)。雑に扱ってよいのは `memory/` だけ (気軽に書き、rule / reference への昇格・整理は気づいた人がその時にやる)。`reference/` は遅延ロードの rule に相当するので、本文の質は rule と同じ水準で書く。

## 追加の前に所属を判断する

1 本足す前に、**既存のどれに属するか / 新設が必要か**を判断する。「思いついたので新ファイル」を既定にしない (フラットな積み上げが地図を失わせる)。既存ファイルの 1 節として書けるならそちらへ足す。

## 本文の書き方

- **知識そのものだけ**。出典・確定待ちの注記・採用側の個別事情・雑談めいたメモは書かない (journal / issue / DR 側へ)。help や spec の形で足りるものに表や節の装飾を足さない
- **必要時にしか読まれない前提で自己完結**に書く (索引を読み返さないと意味が取れない書き方をしない)
- 手順が決まっているならコマンドをそのまま載せる。rule と違い行数の制約は弱いので、具体度を落とさない
- rule は毎ターンロードされるので、冗長さがそのまま token 浪費になる。背景説明は最小限で行動指針を書く
- 他文書の指し方: 常時ロード rule 同士は wikilink `[[名前]]`、参照知識は「reference の `<topic>/<slug>`」、skill は「`<name>` skill」と名前で書く (機械検査される禁則は `rule-writing-guidelines` rule)

## 書いたら確認なしで commit・push まで完結させる

どのプロジェクトのセッションからでも、`memory/` `reference/` への追記は**ユーザに確認せず**完結させる: 本文を書き、`_index.md` を更新し、その 2 つをパス指定で commit し、push まで通す。

```bash
(cd <rules リポ> && jj commit -m "reference: <slug>" reference/<topic>/<slug>.md reference/<topic>/_index.md && just push)
```

- 「越境なので commit しますか」「push しますか」と聞かない。これらのパスは version bump gate の対象外
- 業務固有名詞・個人情報が混ざる時だけ止まる (書き先が privacy / overlay になるため)
- パス指定 commit は必須 (パスなしは他セッションの変更を巻き込む)
