# reference のディレクトリ構成と分割

## トピックで階層化する

1 つのツール / ドメインの知識は 1 つの巨大 md にせず、`reference/<topic>/` にケース・目的・章ごとの md を置き、`reference/<topic>/_index.md` をそのトピックの索引にする。

```
reference/
  _index.md            # トップ索引。<topic>/_index.md へのエントリだけを載せる
  <topic>/
    _index.md          # トピック索引。本文 md へのエントリ
    <slug>.md          # 本文
    scripts/           # リソース (索引に載せない)
```

トップの `reference/_index.md` に載せるのは `<topic>/_index.md` へのエントリだけ (= 索引 → トピック索引 → 本文、と段階的に深める)。索引の形式はどの階層でも同じ (index-conventions)。単独の本文 1 枚で足りるトピックは階層化せず `reference/<slug>.md` に置き、トップ索引の「単独の本文」節に載せる。

## 分割の粒度

**その手順を使う時に 1 ファイル読めば足りる**単位で切る。1 ファイルが大きい手順・runbook は、利用時に一部の知識で足りるならディレクトリを作って分割する。

- 手順・コマンド一覧・テンプレ・トラブルシュート表は積極的に分割する (「ブランチを切る時」「PR を出す時」「詰まった時」は別の場面で読まれる)
- 逆に、片方だけ読むと誤った操作になる内容は同じファイルに置く (例: 破壊的操作とその前提確認)
- 分割したファイル同士は相対リンクで指してよい。ただし本文は自己完結を保つ (他の本文を読まないと意味が取れないなら分割点が間違っている)

## リソースの同梱

skill と同様に、参照知識もスクリプト・テンプレ・付属ファイルをトピックディレクトリに同梱できる。

- 置き場は `scripts/` `templates/` `assets/` (読み物でないものはこの 3 つのどれかに入れる)
- **索引には載せない**。`_index.md` に載せるのは読み物 (`.md`) だけ
- 存在と使い方は本文側に書く (「本トピックの `scripts/foo.py` を使う」)。本文から辿れないリソースは置かない
- `just lint-rules` の索引 1:1 検査はこの 3 ディレクトリを再帰的に対象外にする

## 索引で引けない時の grep フォールバック

索引の発火語に当たらなくても知識がありそうな時は、本文を直接当ててよい。

```bash
rg -il '<語>' <rules リポ>/reference <rules リポ>/memory
```

ヒットのうち該当する 1 ファイルだけ Read する。発火語の漏れに気づいたら索引に足す。
