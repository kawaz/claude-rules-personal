# セッション状態ファイルのロード

前のセッションが残したハンドオフを、後継セッションが 1 回だけ引き継ぐための手順。

## 場所とポインタ

```
${XDG_CACHE_HOME:-$HOME/.cache}/claude-session-state/<project>/latest.md
```

`<project>` は**リポジトリのディレクトリ名そのまま** (前方一致する姉妹リポは別ディレクトリ)。`latest.md` は本文を持たないポインタ:

```
repo: /abs/path/to/repos/github.com/<owner>/<repo>
state: <YYYYMMDD-HHMM>.md
loaded_by:
```

- `repo:` — このハンドオフが管轄するリポの絶対パス (照合キー)
- `state:` — 状態本文の実体ファイル名 (同ディレクトリ、immutable)
- `loaded_by:` — 引き継いだセッションの記録。空なら未消費

## 手順

1. **cwd 照合**: 自分の cwd が `repo:` 配下でなければ、別プロジェクトのハンドオフ。読まなかったことにして通常立ち上げする (姉妹リポの state を誤って引き継ぐのが最悪の事故)。`repo:` が無い旧形式は状態本文の §2 Current Phase のリポ名で同じ照合をする
2. **鮮度チェック**: 状態本文 §2 Current Phase の head (コミット hash) を実機 (`jj log -r main` / `git log`) と照合する。**main が state 記録時より進んでいたら §継続作業指示は失効扱い** — 別セッションが消化した可能性が高い。失効時は指示を実行せず、実機確認の結果と次アクション候補の提示に降格する (他のセクションは背景知識として読んで良い)
3. **`loaded_by:` が空なら**: `state:` の実体を Read し、直後に `loaded_by:` へ 1 行追記する (`  - <ISO時刻> <自分の session-id>`)。以後このハンドオフは自分のもの
4. **他セッションの記録が既にあるなら**: そのハンドオフはその系列に消費済み。自分のものとして採用せず、journal / メモリ / リポの実機確認から通常どおり立ち上がる (その系列はクラッシュしても `claude --continue` で続くため、状態はそちらが正)

> Why: ハンドオフは「1 つの後継セッション」宛て。多重ロードすると 2 系列が同じ状態から分岐して同一 ws を取り合う。

## 継続作業指示 (§10 Recovery Notes 内) の扱い

`loaded_by:` を追記したら、§継続作業指示があるかで分岐する。**無ければ**次アクション候補の優先度を提示して kawaz 判断待ち。**あれば**項目ごとの出どころラベルで分岐する (並行で Monitor / subscribe 等の再起動もここで済ませる):

- `[kawaz 指示]` — 暗黙 approve として即実行 (kawaz の追加確認を待たない)
- `[AI 自律]` — 着手前に**根拠の裏取り**をする。当該作業が触る領域の DR / issue / `docs/QUESTIONS.md` の裁定サマリを grep し、**確定裁定と矛盾しないこと**を確認してから実行する。矛盾を見つけたら実行せず、矛盾点を添えて kawaz に確認
- **ラベルが無い旧形式** — `[AI 自律]` と同じ扱い (安全側に倒す)

> Why: 継続作業指示は「最新のユーザ意図」として即実行される経路。前セッションの AI が自己判断で立てたタスクが同じ重みで流れると、確定済み裁定を AI が単独で覆した結果が、ゼロコンテキストの後継セッションで裏取りされずに実行される。ラベルは「誰の意図か」を後継が復元できる唯一の手掛かりになる。

## 書く側の禁則

**状態ファイルは kawaz または hook の明示指示でしか書かない** (区切りの良さ・context 残量・保険を理由に自発的に書かない)。書く指示が来たら reference の `session-state/write` を読む。
