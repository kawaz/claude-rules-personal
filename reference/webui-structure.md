# webui の構成と画面の組み方

kawaz 製の webui (管理画面・ダッシュボード・PWA) を作る時の構造と画面設計の規約。モダン CSS / JS の採否は memory の `webui-modern-platform-first` を読む。

## 構成

- **部品とトークンは 1 か所に持つ**。デザイントークン (色・余白スケール・字体・角丸) は CSS custom properties を 1 ファイルに、部品 (チップ / 状態ラベル / ボタン群 / 定義リスト / フォーム行 / ダイアログ / ステップ) はテンプレート関数 (またはコンポーネント) を 1 モジュールに置き、全ページがそれを呼ぶ。ページごとに手書き HTML を増やさない
- **ビルドしてよい**。bun なら起動時の `Bun.build` でメモリ上に bundle する形で、成果物をリポに置かずに済む。サーバ側テンプレート + 共通 CSS でもよい。「静的 HTML + fetch で DOM を組む」をページごとに書くのは避ける
- クライアント側も API の応答はスキーマで parse してから使う (TypeScript の水準は rule `typescript-typing`)
- 静的ファイルは内容 hash 付き URL (`?v=<hash>`) + `Cache-Control: no-cache` + ETag。HTML と JS の版ずれを検出したら「再読み込み」を促す
- 外部フォント・CDN は使わない (tailnet 内で外に出ないため)。system-ui 系で組む

## 画面の組み方

- **1 画面に置きすぎない**。一覧ページは一覧とフィルタだけ。「送る」「追加する」のような操作はボタンから dialog か別ページで開く。詳細ページは基本情報と状態の表示が主で、各操作は dialog に分離する
- **操作ボタンは 1 か所にまとめる**。画面の最上部・途中・最下部に散らさない。一覧ならフィルタの直下に並べる。画面下に固定するバーや右上の「+」のような常設の浮きボタンは使わない
- **モーダル dialog**: 必ず modal (`showModal()`) で開き、背景は inert (触れない・スクロールしない)。狭い幅 (〜600px) では全画面にして上下の隙間を作らない (戻るバー + タイトル + スクロールする中身の「専用ページ風」)。広い幅は中央のダイアログ。全 dialog に同じ規則を component 側で持たせる
- **幅の検証は 390 / 600 / 770 / 900 / 1280 の全部で行う**。中間幅で列が壊れるのを見落としやすい。列の切り替えは viewport でなく container query で判定する
- 状態ラベル: 「済」は塗り点、「未」は中抜き。無効化・アーカイブ済みのものは ラベルだけでなくページ全体 (ヘッダの減色、上部の帯、操作ボタンの非表示) で分かるようにする。灰色は「無効」の意味に読まれるので、完了状態には使わない
- textarea は例を placeholder に書かず初期値として入れる (入力し始めた瞬間に消える placeholder は参考にならない)。高さは `field-sizing: content` で内容 + 1 行に自動で合わせる
- 文言は常体で簡潔に。ボタンは動詞。保存されている物の説明は「何が・誰が書くか」が 1 文で分かる形

## デザイン案の決め方

複数案を独立した worker に brief (対象ユーザ・機能要件・ダミーデータ) だけ渡して自由に作らせ、静的モックとスクリーンショットを artifacts に置いて比較ページで選ぶ。既存の方針ファイルは渡さない。採用した案の worker にそのまま本実装を出す。スクリーンショットを置く時は画面ごとに幅を並べた index.html も作る (png のファイル名の羅列は見比べられない)。
