# agy の権限と、書ける範囲の囲い方

非対話 (`-p`、stream-json) では、agy は権限を人に聞けない。聞く必要がある道具を使おうとすると、その場で拒否される (終了コード 0、`status` は `SUCCESS` のまま。見分け方は reference の `agy/headless` の「失敗の見分け方」)。

確かめた版: 1.5.13〜1.5.15 (macOS、2026-11-21〜25)。

## モードごとにできること

| 指定 | ファイルを読む | ファイルを書く | シェルのコマンド | `run_workflow` |
|---|---|---|---|---|
| 何も付けない | 可 | 不可 | 不可 | 不可 (拒否されて会話が打ち切られる) |
| `--mode plan` | 可 | 不可 | 不可 | 未確認 |
| `--mode accept-edits` | 可 | 可 | 不可 | 未確認 |
| `--mode auto` | 個人のアカウントでは使えない (`--mode auto is not available for this account` と出て、既定のモードで動く) | | | |
| `--dangerously-skip-permissions` | 可 | 可 | 可 | 可 |

- 別のディレクトリにも書かせる時は、`--add-dir <ディレクトリ>` と書ける指定 (`--mode accept-edits` か全許可) を併せる
- 依頼の本文に「シェルのコマンドは使えない。ファイルを読む・探す・書く道具だけを使う」と書くと、多くの場合は守られる。守られずにコマンドを使おうとして、何も書かずに終わる事もある

## 特定のコマンドだけ許す (`--settings`)

`--settings` に JSON (かそのファイルのパス) を渡すと、その回だけの設定を足せる。`permissions.allow` に `command(<コマンド>)` を書くと、全許可にしなくてもそのコマンドだけが通る。

```bash
agy -p 'Run `uname -s`.' --settings '{"permissions":{"allow":["command(uname -s)"]}}'
```

決まったコマンド (テスト、lint、build) だけを使わせたい時は、全許可よりこちらを使う。

## `--sandbox` は当てにならない

| 指定 | 結果 |
|---|---|
| `--sandbox` + `--dangerously-skip-permissions` | 何も縛らない。作業ディレクトリの外 (`/tmp` を含む) への書き込み、`/etc/hosts` の読み取り、外部への HTTP がすべて通った |
| `--sandbox` だけ、または `--settings` で許したコマンドと併せる | シェルのコマンドが `sandbox-exec` の中で走ろうとして、シェル自体が起動できずに終わる (`sandbox-exec: execvp() of '/etc/profiles/per-user/<user>/bin/zsh' failed: Operation not permitted`、終了コード 71)。ログインシェルが nix のプロファイルにあり、sandbox の許可に入っていないためと推測 (未確認) |

- `stream-json` の `init` の `permission_mode` は、指定によらず `proceed-in-sandbox` だった (ドキュメントは既定を `request-review`、全許可を `always-proceed` と書いている)
- 全許可で流す時に、書ける範囲を縛るものは agy の側に無い。作業場所を決めても、それはモデルへの依頼にすぎない

## 広い権限で流す時の囲い方 (案。未検証)

シェルを使えないと、ファイルの検索・リネーム・削除・検査のコマンドの実行ができず、頼める仕事が狭くなる。全許可で流すなら、書ける範囲を外から囲う。

- コンテナに、必要なディレクトリだけをマウントする。読むだけの物は読み取り専用、書かせる物だけ書き込み可にする
- 確かめる事: Linux 版の `agy` がコンテナで動くか、ログインの資格情報をどう渡すか。資格情報を中に置くと、全許可のエージェントはそれも読める。API のためにネットワークは開けるので、中で読める物は外に出せる前提で、見せる物を選ぶ

## 入力を守る

元のリポを直接見せない。写し (`git archive` の展開か clone) を作って、そこで作業させる。

- 読ませるだけの時は、写しを書き込み禁止 (`chmod -R a-w`) にする
- 直させる時は、clone の push 先を外しておく。結果は clone の中のコミットとして受け取り、採る物だけを元のリポに入れる
- 送った中身は、外のサービスに出る。個人情報や業務の情報を含むリポを渡す時は、持ち主の明示の指示がある時だけにする
