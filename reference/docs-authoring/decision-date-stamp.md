# 外部情勢に依存する選定には判断基準日を添える

アルゴリズム・ライブラリ・プロトコル・プラットフォーム対応のように、**その時点の外部情勢を根拠に選んだもの**は、選定を書いた文 (DR の決定、reference の推奨、設定の既定値) に「判断基準日」を添える。

```
- `alg` は `"Ed25519"`。`"EdDSA"` は曲線が多義なので使わない。**alg 選定判断基準日: 2026-10-27** (選定を変えたらこの日付も一緒に更新する)
```

## 書き方

- 書式は `<対象> 選定判断基準日: YYYY-MM-DD` と、括弧で「選定を変えたらこの日付も一緒に更新する」の 1 文。どの選定に対する日付かが分かる名前を付ける (文書全体の日付にしない)
- 日付は**選定を判断した日**で、文書を書いた日や最終更新日ではない。文書を触っても選定を再評価していないなら日付は動かさない
- 再評価して同じ結論になった時も日付を更新する (「その日に見直した」こと自体が情報)

## 対象

- 暗号 alg・鍵長・ハッシュ関数 (情勢で危殆化する)
- ライブラリ・フレームワーク・ランタイムの選定 (メンテ状況・対応状況が変わる)
- プラットフォーム対応の判断 (「どの環境でも困らない」「Ed448 は環境が足りない」のような現状認識)
- 標準・RFC の採用 (後続の RFC で置き換わる)

仕様由来で情勢に依存しない決定 (ドメインモデルの形、責務分離、命名) には付けない。日付を付けると「いつか見直すもの」と読まれるので、見直す必要が無い判断には不要。

## no-historical-noise との関係

`no-historical-noise` rule が消すのは「以前は X だった」「v0.3 で変更」のような**経緯**。判断基準日は経緯ではなく「この判断が依拠した情勢の時点」で、読者が今も有効かを疑うきっかけとして**現在価値を持つ**。DR の `Status:` 行が判断の有効性を示すのと同じ役割を、文書内の個別の選定に対して持たせるもの。2 年後・10 年後に読んだ人が「この間に情勢は変わったか」と立ち止まれることが目的。
